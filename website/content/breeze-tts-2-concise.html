01下载 Windows x64 安装包

适用于 Windows 10 / 11 的 Intel 或 AMD x64 电脑。预留约 10 GB 空间，下载 VoiceStudio v0.5.7-beta.2 · Windows x64 EXE，并按同一发布页的 SHA256SUMS.txt 校验。这个安装包不是下面的便携 ZIP；Windows ARM 机型不在本教程范围。

02完成应用的首次设置

运行安装程序，选好安装位置；首次启动按应用提示安装本地运行环境（Install local runtime）。应用会准备所需依赖，不需要另外照搬本文 PyTorch Skill 的环境。希望放到其他盘，可在首次设置的 App environment 旁选择 Change…，确认界面列出的环境、数据与模型目录。

03安装 Breeze 模型与 audio.cpp

进入 Settings → Models，安装 Breeze-TTS-2 对应权重，在 audio.cpp 引擎行点 Install runtime。再到 Model Catalogue 的 TTS 页，确认 Breeze-TTS-2 Q8_0 已安装，并明确选择 audiocpp / Use；默认引擎不一定是 Breeze。

VoiceStudio 在 Win / Mac 上使用 audio.cpp 专用的 Q8_0 权重，约 4.73 GiB。下方便携教程的 3.57 GB GGUF 来自另一套实现，不能按文件名直接替换。AMD 显卡需使用带 Vulkan 支持的 audio.cpp 运行时；PyTorch 引擎的 CUDA 加速不适用于 AMD。

04先生成一句短音频

在音色设计界面选 Breeze-TTS-2 / audiocpp，填一句中文和声音描述后生成，再播放检查。声音设计可从 CFG 4 开始；克隆则提供参考音与准确逐字稿。首次生成会启动引擎，遇到错误先看应用的引擎状态与日志。

之前为什么推荐 Windows 便携版？

因为本文在 Windows 上从下载、解压到生成实际跑通的是便携版，不代表 VoiceStudio 不能在 Windows 用。VoiceStudio 把环境、模型和操作集中在图形界面，更适合想少碰命令的新手；本文目前尚未实测它的 Windows 安装与生成，因此保留下面已验证的 NVIDIA 便携路线供选择。

依据：v0.5.7-beta.2 Windows 安装说明、audio.cpp 引擎说明。安装包和具体后端是否适合本机，仍需实际启动和生成确认。

01准备系统和显卡驱动

需要 Windows 10/11 64 位（Intel/AMD x64）、支持 AVX2 的 CPU，以及约 6 GB 空闲磁盘空间。新电脑先装好显卡驱动，再继续下面的步骤。

在“设备管理器 → 显示适配器”确认 NVIDIA 显卡型号，到 NVIDIA 官方驱动下载页选择匹配的驱动。按安装程序提示完成，要求重启时先重启。

本 Windows 发布包依赖驱动提供的 Vulkan 运行库（vulkan-1.dll）。免装 AI 环境不等于免装驱动；缺少这个文件时，单加 --cpu 也解决不了。无需安装整套 Vulkan SDK 或 CUDA 工具包。

01 参考录音与逐句生成

这期从自己的录音中截取 6.55–15.50 秒，得到 8.95 秒的参考片段，转为 24 kHz 单声道，保存为 ref.wav。ref.txt 写完整、逐字一致的文本，包括重复和口头语。换成自己的录音时，也必须一起更换逐字稿。

参考音频和逐字稿先复制到纯英文工作目录，例如 D:\BreezeWork\。该项目曾在含中文路径时遇到进程静默退出、只留下空 WAV；这是当时的排错经验，不能据此认定所有中文路径都会失败。私人原始录音与个人目录不随本文提供。

字幕保留原稿；另外准备 lines_say.json 给 TTS 念。一句一条，示例如下：

lines_say.json · 示例
[{"id":"L01","text":"你好，这是我的第一段声音克隆配音。"}]

当时使用已配置好的独立 Conda 环境，解释器位于 envs\qwen3-tts\python.exe，加载魔搭下载的 BreezeBlue/Breeze-TTS-2 原版权重。环境名称是本机历史命名，实际运行的是 Breeze。项目自定义入口为 tools/audio/tts_clone.py，模型只加载一次，循环生成每句 WAV。

公开脚本包 · 先填写源码和原版模型路径
python tts_clone.py --repo D:\Breeze\breeze-tts --model D:\Breeze\Breeze-TTS-2 --lines lines_say.json --ref ref.wav --ref-text ref.txt --out vo_raw --seeds 42 --cfg 1 --eager --work-dir D:\BreezeWork\temp

先激活对应环境，在解压后的脚本目录运行。--repo、--model 和 --work-dir 是去敏公开版新增参数；示例盘符需改成自己的位置。可先加 --validate-only 检查输入，再去掉它正式生成。补一句用 --only L02；覆盖已有结果需明确加 --overwrite，或换输出目录。此命令不能粘到 GGUF 程序目录运行。原版安装和官方单句入口见官方 PyTorch 仓库。

02 显存够用再加速：eager 与快速路径

这一期实际使用 eager 省显存路径。脚本传入 --eager 后，fast_all=False，不启用那组 CUDA Graphs / 编译加速。当时 TTS 约占 8 GB 显存，其他任务已经占了约 22 GB，因此没有选择快速路径。

同一个自定义脚本去掉 --eager，会设置 fast_all=True，启用 CUDA Graphs 和 torch.compile 相关快速阶段。脚本记录这台机器首次编译约 75 秒，缓存后准备约 20 秒，预热峰值约 26 GiB，之后约 8 GiB。这些是当时环境的记录，不是最低显存要求，也没有在本文重测加速倍数。

操作顺序：先保存并结束自己不需要的 GPU 任务，给首次编译、预热留足显存；先用一句短文本验证快速路径，再批量生成。显存不足、编译失败或结果异常时，加回 --eager 退回已用过的路径。不要只按预热后的占用估算所需显存。

注意两个不同设置：模型加载时的 attn_implementation="eager" 是 attention 实现；脚本的 --eager 控制是否关闭快速阶段。这个项目即使启用快速阶段，attention 参数仍然是 eager。

当时 Windows 快速路径的兼容配置是 triton-windows<3.5，并在导入 torch 前设置下面的环境变量，避开当时 static launcher 的 32 位整数溢出问题。该组合依赖当时的 PyTorch、Triton 与源码版本，不建议在新环境中盲目降级套用。

PowerShell · 当时 Windows 项目的兼容设置
$env:TORCHINDUCTOR_USE_STATIC_CUDA_LAUNCHER = "0"

官方原版 infer.py 用 --fast-all 开启快速路径；本项目封装则默认开启、用 --eager 关闭。不要把两个入口的参数混用。官方当前说明可用于核对模式和环境要求，本文 26 GiB 是本机历史预热记录。

04 让专有名词更好读，再检查漏字

字幕用原稿 lines.json，朗读用 lines_say.json。只把易误读的形式改成读音：GLM-5 →“GLM 五”，Harness² →“Harness 平方”，Gemini 3.5 →“Gemini 三点五”，64.2 →“六十四点二”；72.4、75.7 同理。

第 2 句第一次漏读“五”。后来加逗号分隔型号与数字：“原本，GLM 五，只有六十四点二分，Gemini 三点五 Flash，有七十二点四分。”保留 Seed 42 和其他参数，只补这句，再核对。

当时逐句用 faster-whisper large-v3，设置 language=zh、beam_size=5，提示词加入 Google、GLM、Gemini、Harness、Codex，辅助检查漏字。另用 Whisper medium 的 word_timestamps 对齐画面关键词。转写和时间戳都可能出错，最终仍需对照原文试听与校正。

05 成品语速 1.25 倍：生成后的处理

这里加快的是成品语速，不能算作模型推理提速。这期对每句原始 WAV 使用 FFmpeg 的 atempo=1.25，变速后再裁首尾静音。只做变速的命令示例：

已有 FFmpeg · 单句变速示例
ffmpeg -i L01_s42.wav -af "atempo=1.25" -ar 24000 -ac 1 -c:a pcm_s16le L01_fast.wav

项目裁静音的方法：在归一化到 −1～1 的浮点波形中，找到绝对振幅大于 0.012 的首、尾采样点，开头多留 20 ms、结尾多留 80 ms。这是这期的阈值，轻声或气声可能被误裁；处理后需检查起音和尾字，不能作为所有声音通用值。

公开版在脚本目录运行下列命令，会生成 prepared/vo/ 和 prepared/plan.json；再次运行请换新的输出目录。可加 --bpm 80 把句子起点放到后续节拍，也可加 --bgm D:\MyAudio\licensed-bgm.wav 使用自己的音乐。

公开版 · 变速与裁静音
python timeline.py --lines lines_say.json --input vo_raw --out prepared --seed 42 --speed 1.25 --gap 0.25

处理后的每句按 BGM 的小节、节拍安排起点，画面跟随实际配音时长。逐字时间戳要对应最终音频；若沿用变速前的时间戳，需要按变速比例及裁切偏移换算。

06 统一音量，让 BGM 给人声让位
  • 逐句统一音量：mix.py 对绝对振幅大于 0.01 的样本计算 RMS，再缩放到 0.12；并非对整句所有静音一起计算。
  • BGM 自动压低：有人声时降低 7 dB，压低的时间常数 80 ms，恢复的时间常数 400 ms。数值取自这期时间轴与混音脚本。
  • 最后统一响度：loudnorm=I=-14:TP=-1.5:LRA=11。这是目标值，当时成片记录为约 −14.7 LUFS、峰值 −1.4 dBFS；后者是数字峰值读数，不能直接当作真峰值 dBTP。
公开版 · 混音
python mix.py --plan prepared\plan.json --out final_mix.wav

公开版相对音频路径以 plan.json 所在目录为准，没有 BGM 也能运行，输出是 48 kHz 双声道 PCM WAV。短音乐会循环，需自行检查循环点；原项目的音效、音乐剪段和画面事件未打包。

混完之后再测量、试听，避免削波、背景音乐盖住人声。RMS 对齐、BGM 压低和整体响度标准化分别解决不同问题，不是把同一个“音量”重复调三遍。

核对依据：本地 harness2 的 tts_clone.py、timeline.py、mix.py，以及原版 runtime.py 与 fast_streaming.py（2026.10.25 核对）。官方原版文档可查模式、快速入口与许可。模型权重及自托管输出限研究和非商业用途；商用请支持开头的官方服务并选择具备商用权限的方案。

遇到问题

找不到模型？

确认文件下载完整、名称是 breeze-tts-2-q8_0.gguf，且与 breeze-server.exe 在同一层。启动文件也要在这一层，不能留在“下载”文件夹里。

缺少 vulkan-1.dll？

预编译包需要显卡驱动提供这个运行库，添加 --cpu 也不能消除它的 DLL 加载依赖。可更新厂商驱动，或按 CPU 路线编译关闭 Vulkan 的纯 CPU 程序。

网页打不开？

先等校验、加载和预热完成。若旧程序占用了端口，先关旧窗口；也可在手动命令中把 8088 改为 8098，再访问 http://127.0.0.1:8098/。还需确保相邻的 8099 端口空闲。

生成很慢？

检查启动窗口是否显示 Vulkan 显卡，是否回退到了 CPU，并检查显卡驱动。本文没有实测 CPU 或其他显卡的速度。

让声音灵动的几个技巧

  • 描述写人和场景，例如“带着笑意”“像在跟老朋友聊天”，比堆音调、语速数值更符合这次创作经验。
  • 一句台词生成一条；用逗号切短句，省略号表现犹豫，例如“嗯……好像”。
  • 在句首尝试 [笑]、[叹气]，片中用它们引导先笑、先叹气再说话；具体效果需听生成结果。
  • 片中后期切掉首尾静音，句内超过 0.3 秒的停顿压短；旁白整体加速到 1.12 倍，角色声音保持原速。

timeline.py --speed 1.12 可用于旁白，角色另用 --speed 1；它会裁首尾静音，不会自动压缩句内超过 0.3 秒的停顿，这部分需另行编辑并检查气口、尾字。纯克隆、声音导演与后期变速是不同操作，可按作品需要单独使用。

设计和导演要显式设 CFG 4，纯克隆用 CFG 1；各角色、情绪可单独选用，不必照搬片中流程。完整说明也已收入本页开头的 Skill 下载包。
